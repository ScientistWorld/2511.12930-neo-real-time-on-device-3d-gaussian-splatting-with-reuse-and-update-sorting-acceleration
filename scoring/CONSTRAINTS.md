# Scientist Constraints

## Workload

Candidates must use the deterministic workload generated by `data/synthetic_workload.py` with the same scene definitions, frame count, chunk size, and seed unless a new experiment is added under a new scoring key. The benchmark is about sorting strategy, not making the temporal trace easier.

## Output Contract

Candidates must write an artifact compatible with `eval/evaluate_sorting.py`: per-scene ordering-quality metrics and traffic accounting under `outputs/`. Evaluation must remain in `eval/` and must not import candidate method code.

## Traffic Accounting

Candidates must report table-entry traffic using the same 8-byte Gaussian entry convention and must include all table reads/writes needed by their sorting strategy. Omitting insertion, deletion, or metadata update traffic is not allowed.

## Compliance Checklist

- [ ] Uses the provided workload generator settings for `synthetic_temporal_sorting`
- [ ] Writes compatible artifacts under `outputs/`
- [ ] Does not modify `eval/` to import or call candidate method code
- [ ] Counts all required table-entry reads and writes in `traffic_MB`
